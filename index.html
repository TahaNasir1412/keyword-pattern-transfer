Pattern Transfer

Keyword candidate builder for pages the tools say have no volume

Paste the keywords from pages you have already researched. This maps what has an ancestor, expands the concepts into keywords that were never in your list, then derives what no previous page could have told you. It does not check volume. It builds the list you take to a volume tool.

How this works, with examples and a diagram

The page you are building

Three required fields. The API key comes from your environment variable, nothing to set up here.
02

Define the scope

What this service is, and what it is not. Everything downstream is held to this.

Before any keyword work, the model reads your service term and writes down exactly what it means: what the machine is, which jobs belong on this page, which adjacent services must stay off it, and which readings of the phrase are not yours. You check it, edit it, and confirm. Nothing runs until you do.

Two short calls, usually under fifteen seconds. The button shows which one is running.

One block per page. Two or more pages makes the pattern validation reliable.
One keyword per line. Volume is optional. Put it after a tab, comma or space if you have it, or leave it off entirely. This tool never checks volume, it only builds the candidate list, so a keyword with no number is just as useful here.
